\section{PageRank Kernel Implementation using \api{}}
\label{appendix:pagerank_graphapi}
\begin{lstlisting}[label={lst:pagerank_graphapi}, caption={GAPBS PageRank kernel modified to use~\api{}}, style=cpp, captionpos=b]
  pvector<ScoreT> pagerank(GraphEngine& graph_engine,
                         int thread_num,
                         int max_iters,
                         node_id_t num_nodes,
                         node_id_t max_node_id,
                         double epsilon = 0)
{
    pvector<ScoreT> src(max_node_id, 0);
    pvector<ScoreT> dst(max_node_id, 1 / num_nodes);
    pvector<node_id_t> deg(max_node_id, 0);

#pragma omp parallel for
    for (int i = 0; i < thread_num; i++)
    {
        GraphBase* graph = graph_engine.create_graph_handle();
        NodeCursor* node_cursor = graph->get_node_iter();
        node_cursor->set_key_range(graph_engine.get_key_range(i));

        node found = {0};
        node_cursor->next(&found);

        while (found.id != -1)
        {
            deg[found.id] = found.out_degree;
            node_cursor->next(&found);
        }
        node_cursor->close();
        graph->close(false);
    }

    for (int iter = 0; iter < max_iters; iter++)
    {
        double error = 0;
#pragma omp parallel for reduction(+ : error)
        for (int i = 0; i < thread_num; i++)
        {
            GraphBase* graph = graph_engine.create_graph_handle();
            InCursor* in_cursor = graph->get_innbd_iter();
            in_cursor->set_key_range(graph_engine.get_key_range(i));

            adjlist found;
            in_cursor->next(&found);

            while (found.node_id != -1)
            {
                ScoreT incoming_total = 0;
                for (node_id_t v : found.edgelist)
                {
                    incoming_total += src[v];
                }

                ScoreT old_score = dst[found.node_id];
                dst[found.node_id] =
                    (1 - kDamp) / num_nodes + kDamp * incoming_total;
                error += fabs(dst[found.node_id] - old_score);
                src[found.node_id] = dst[found.node_id] / deg[found.node_id];

                in_cursor->next(&found);
            }

            in_cursor->close();
            graph->close(false);
        }
        printf(" %2d    %lf\n", iter, error);
        if (error < epsilon) break;
    }
    return dst;
}
\end{lstlisting}

Let us examine, for instance, our modifications to the \ac{GAPBS} PageRank implementation to 
use ~\api{}, as shown in~\autoref{lst:pagerank_graphapi}.
The basic structure of the PageRank implementation is unchanged from the original \ac{GAPBS}, but with changes introduced to use the iterator classes and the \api{}.
To use OpenMP construct \unix{parallel for}, usually one can just add a pragma directive before the loop, and the compiler will automatically parallelize the loop.
However, automatic parallelization based on the loop construct is not possible in our system because we need each thread to construct its private graph handle and iterator.
Additionally, automatic parallelization does not allow us to statically assign iterator ranges to the threads as we do in the \code{calculate_thread_offsets()} method.

To remedy this, we have to manually parallelize the loop and assign each thread a range of nodes to work on.
We use the \code{calculate_thread_offsets()} method to calculate the key range for each thread during GraphEngine instantiation. 
In the OpenMP parallel block, each thread uses the \code{get_key_range()} method to get the key range for itself.

\ac{GAPBS} uses a few utility classes that it uses to store algorithm state and updates.
The \code{pvector} is a modified vector class that allows parallel initializations and resizing.
C++ standard library's \code{std::vector} is not thread-safe and always serially initializes the elements when resizing. 
\code{pvector}, on the other hand, initializes a new vector in parallel but does not initialize the elements when resizing.
\code{sliding\_queue} is a double-buffered queue class that allows atomic appends to a buffer that are not visible until the \code{SlideWindow()} method is called.

These utility classes are memory-based and are destroyed when the application is closed.
\project{}, however,  does not wish to lose any algorithmic state that is stored in these utility classes, and strives to provide a mechanism to persist this state to disk for future use.
To do so, we modified the \code{pvector} and \code{sliding_queue} classes to use an \unix{mmap} region as their internal buffer for storing the state.
The basic functionality remains unchanged, however, the destructor of these classes now calls the \code{msync()} system call to persist the state to disk.
