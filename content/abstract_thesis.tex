\chapter{Abstract}

Graph-structured data is common, and many data domains can be intuitively expressed as graphs.
As large graphs become ubiquitous, there is an increasing interest in storing them and processing them efficiently at scale.
Graphs are rarely stored natively; most graph data is extracted from data resident in some persistent database and then transformed into an in-memory representation that can be used for graph-wide statistics. 
State-of-the-art graph processing systems are built around these extract-transform/preprocess-load (ETL) pipelines; this process must be repeated every time the data changes.
Traditional relational databases have been avoided for running whole-graph analytics for many reasons ranging from an unintuitive interface to poor performance.
Graph databases work well for storing and managing dynamic graph data; however, they are often overlooked as a candidate for long-running iterative graph algorithms.
This is the central dichotomy of graph data management: graph databases allow for persistent storage of graphs in a native representation, but they are outperformed by specialized graph processing systems that require a costly ingest and preprocessing phase before executing efficient graph analytics queries.
\\\\
This thesis claims that it is possible to store and manage dynamic graph-structured data in a performant and extensible way.
We designed and implemented a transactional graph database system based on a production-ready general-purpose key-value storage engine, providing an API that lets users interact with their data efficiently.
Our system is extensible and allows the user to store multi-layer property graphs and gives them a choice of three different storage formats.
The API is flexible enough that users can express their graph computations in terms of vertex or edge operations; the system itself does not restrict the paradigms that can be used.
% The API allows the user to write algorithms in any style, and the system itself does not restrict the paradigms that can be used.
Our system is designed for a single-node, single-socket environment, and we show that high performance on graph analytics tasks can be achieved without scaling to a cluster.
Additionally, we show that our system scales to large graphs that scale to billions of edges and can handle transactional and analytical workloads simultaneously.
\\\\
Our architecture provides the best of both worlds: the data management capabilities one expects from a database, with the performance of a specialized graph processing system with none of the ETL or preprocessing costs involved in those solutions.
